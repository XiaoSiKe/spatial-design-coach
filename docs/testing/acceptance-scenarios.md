# 验收情境

## 测试原则

- 在“学生请求进入 Skill → 得到诊断、行动和下一轮证据”的最高外部 Seam 验收。
- 使用真实感但合成、或获得授权并去标识化的学生材料；不向执行者透露预期答案。
- 检查可观察行为，不锁定固定措辞、标题数量或模型内部推理。
- 高风险事实无法核验时应明确限制；外部工具结果必须经过设计复核。
- 幽默只有在紧跟专业判断或动作时才算通过。
- 机器可读的单轮标准见 [`cases.json`](../../tests/evals/cases.json)，多轮状态与 Artifact 标准见 [`journeys.json`](../../tests/evals/journeys.json)。

## 触发范围

应触发：设计课、建筑方案、城市设计、规划设计、景观设计、场地设计、任务书、概念落地、方案没设计感、方案评图、教师反馈、交图救火、展板、汇报和答辩。

不应触发：软件架构、Logo／平面品牌、产品 UI，以及与空间设计课无关的单独 GIS、CAD、建模或 PPT 操作。若已在设计项目会话中，这些操作应被识别为外部能力移交。

| ID | 输入情境 | 关键通过条件 |

| SDC-010 | 环境没有所需外援 | 明确未完成；给移交单、人工路径、验收清单和待验证结论 |
| SDC-011 | 图纸很多但展板叙事混乱 | 每张图承担一个任务；建立阅读顺序；指出删、补、重画与最终尺寸检查 |
| SDC-012 | 答辩被质疑逻辑、受益者、可行性和证据 | 用主张—证据—限制—回应；允许未知并给验证计划 |

| ID | 输入情境 | 关键通过条件 |
| --- | --- | --- |

## 通用判定

每个应触发情境还必须满足：

- 从学生实际材料或明确标记的低信息假设出发；
- 当前诊断专业、具体，并区分已检查 Artifact 与学生文字描述；
- 给出按优先级排列的 1–3 个动作和下一轮通过条件；
- 不伪造场地、访谈、数据、引用、规范、模型、计算或文件；
- 不替学生确认关键设计立场和取舍；
- 技术能力正确路由或诚实降级；
- 外部 Adapter 不静默修改锁定决定；
- 诙谐表达不稀释专业判断、风险与学术诚信边界。

## 发布检查

- `SKILL.md` 不超过 200 行；八个运行时 reference 合计不超过 1,400 行。
- 仓库验证器、Agent Skills validator、Skill Creator validator 和 Plugin validator 通过。
- 本地发现、隔离复制安装和远程 commit SHA 发现通过。
- 沙盒初始化幂等，学生修改的 `PROJECT.md` 不被覆盖，原始文件不被写入。
- 24 个单轮案例无关键违规；14 个高风险案例和 8 个多轮 journey 均额外独立复跑两次。
- 6 个合成 studio packet 的 manifest、可编辑 SVG、PNG、任务书、反馈和版本说明完整且无个人数据。
- Markdown 链接、标题层级、YAML／JSON、文件末尾、行尾和 `git diff --check` 通过。
- 无占位符、旧路径、未校验的重复权威文案或缺失 provenance 的上游仓库。
- 完整评测报告 commit 与 HEAD 相同，发布资格检查给出通过结果。
