# ADR-0001：轻量核心与能力路由

- 状态：已接受；运行时 reference 数量约束由 ADR-0002 补充
- 日期：2026-08-31
- 适用版本：`0.1.0` 起

## 背景

设计课横跨问题定义、空间推演、GIS、制图、CAD／BIM、参数化建模、视觉表达、演示和文档制作。把这些能力全部纳入同一个 Skill，会带来庞大的运行时上下文、重复的软件知识、快速过期的接口说明和复杂的许可证边界；但完全不处理它们，又无法帮助学生把设计课作业推进到交付。

项目需要在“端到端帮助学生完成设计”与“保持专业、轻量、可维护”之间作出稳定选择。

## 决策

采用“设计教练核心 + 宿主能力路由”架构。

核心负责：

- 从项目任务书建立项目卡并诊断当前卡点；
- 组织七阶段设计工作流、成长／救火模式和行动型评图；
- 维护设计命题、方案取舍、跨尺度关系与成果叙事的一致性；
- 判断是否需要专业能力，定义设计目的和验收标准；
- 验证外部产物，并解释它怎样影响设计判断。

核心不实现 GIS、遥感、空间统计、CAD、BIM、参数化、图像生成、PPT、PDF 或网络检索。运行时按五类能力发现当前宿主已经安装的 Skill／MCP：

```text
research-current
geospatial
cad-modeling
visual
presentation-document
```

能力路由不绑定特定仓库，不自动安装第三方工具，也不复制外部代码。移交必须包含能力、设计目的、当前阶段、输入、明确任务、不得改变的决定、验收标准和返回要求。没有合适外援时，核心输出人工步骤与验收清单，并明确未完成的技术工作。

外援结果不得直接成为设计结论。教练必须复核它支持或推翻的设计假设、方案需要的调整，以及仍需人工判断的限制。

`0.1.0` 的运行时包只包含一个入口、五个按需 reference 和界面元数据；不创建脚本、素材库、全文文献库、案例数据库或外部 Skill 镜像。`0.2.0` 继续保持同一原则，但按 ADR-0002 增加两个有真实 Interface 的 reference，仓库测试仍不进入运行时。

## 备选方案

### 将全部能力内置到一个 Skill

优点是单仓库看似完整，缺点是上下文和维护成本过高、专业工具重复建设、版本快速失效，并扩大许可证与供应链风险，因此拒绝。

### 只做设计教学，不参与成果推进

优点是范围最简单，缺点是无法回应学生的现实截止时间，也不能把设计意图可靠地传递到地图、模型和汇报，因此拒绝。

### 固定依赖一组推荐仓库

优点是路径确定，缺点是宿主能力不同、第三方项目会更新或停更，而且容易把外援的实现细节变成核心 Interface，因此拒绝。

## 影响

正面影响：

- 核心上下文集中于真正的设计判断和学生辅导。
- 可利用宿主已有专业能力，而不重复造轮子。
- 外部工具可以替换，设计工作流与验收合同保持稳定。
- 许可证、安全和版本风险被隔离在能力移交的 Seam。

代价与约束：

- 不同环境的可用能力不同，必须提供诚实的降级路径。
- 外援移交与返回验证成为必需步骤，会增加少量交互。
- 核心不能宣称已完成未实际执行的计算、制图或文件交付。
- 新能力只有在真实学生情境反复证明必要时才进入路由分类；不得为单一工具增加专用核心 Module。
