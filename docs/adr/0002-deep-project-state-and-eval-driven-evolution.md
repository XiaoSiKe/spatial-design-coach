# ADR-0002：Deep 项目状态与评测驱动演进

- 状态：已接受
- 日期：2026-08-31
- 适用版本：`0.2.0` 起
- 补充：[ADR-0001](./0001-lightweight-core-and-capability-routing.md)

## 背景

`0.1.0` 已能从任务书推进到评图和答辩，但项目卡、命题、方案取舍、假设、锁定决定、成果状态和能力移交分别出现在多个运行时 reference 中。学生换阶段、进入救火或接收外援结果时，没有一个稳定 Interface 说明哪份状态是当前真相。

同时，十二个 Markdown 情境只能人工阅读，仓库无法持续证明安装、触发、模式切换、能力路由和作者性保护没有退化。继续增加理论或功能而没有共同状态与回归证据，会扩大 shallow 的文档表面。

## 决策

新增 deep 的“学生项目状态” Module。它集中维护项目范围、当前阶段、主导矛盾、命题、方案取舍、事实与假设、锁定决定、成果状态、下一轮 Artifact 和通过条件。其他运行时 Module 读取或更新同一状态，不维护平行记忆。

项目状态默认只在当前会话中存在。只有学生明确要求时才导出续航快照或写入文件；续航快照是可审阅的工作记忆，不是事实证明或完成证明。

新增按需加载的“当代设计挑战” Module，只在存量利用、碳与资源、气候适应、空间正义、参与维护、分期与不确定性影响具体决定时加载。它不扩张为百科全书。

运行时从五个 reference 增加到七个。新增的两个 Module 都有独立 Interface 和可观察行为；测试脚本、情境数据、研究池和 CI 留在运行时包外，因此继续符合轻量核心决策。

建立仓库级验证 Module：

- 静态验证 Skill、Plugin、元数据、链接和文档一致性；
- 结构化维护 24 个行为情境；
- 在隔离目录验证安装与发现；
- 使用独立执行者与评判者做前向测试；
- 行为改变必须同时更新情境和证据。

“训练 Skill”在本项目中表示评测驱动地改进 instructions 和 references，不表示训练模型权重，也不授权收集未同意的学生资料。

## 备选方案

### 继续让每个 reference 自己保存状态

实现最少，但救火清单、能力移交和方案取舍会继续漂移，学生也难以跨对话恢复，因此拒绝。

### 建立持久数据库或学生画像

可跨项目积累信息，但扩大隐私、同意、删除和错误归因风险，且不是轻量 Skill 的必要能力，因此拒绝。

### 只增加更多透镜和案例

知识数量会增加，但无法修复低信息、项目连续性、作者性和发布验证问题，因此拒绝。

## 影响

- 设计推理、评图、救火、交付和外部 Adapter 共享同一项目状态，获得更高 Leverage。
- 状态冲突、作者性确认和假设升级集中在一个 Module，获得更强 Locality。
- 仓库增加测试和 CI，但它们不进入学生 runtime。
- 维护者需要为行为改变补充情境，并对来源、许可证和学生数据授权负责。
