# ADR-0003：单作业沙盒与文件化项目状态

- 状态：已接受
- 日期：2026-08-31
- 适用版本：`0.3.0` 起
- 补充：[ADR-0002](./0002-deep-project-state-and-eval-driven-evolution.md)

## 背景

`0.2.0` 将任务书、命题、决定、证据、成果和下一步集中为学生项目状态，但默认只存在于当前会话。建筑学院设计作业通常持续数周，包含大量文件、反复评图、多个专业 Adapter 和最终交付；仅靠聊天快照无法稳定判断哪个版本是正式状态，也不能可靠保护原始文件或追踪 Artifact 依赖。

产品目标已收敛为：学生在一个独立项目沙盒中使用 Skill 完成一项设计作业，而不是建立跨课程的学生画像。

## 决策

在可写项目沙盒中创建 `studio/PROJECT.md`，作为该作业唯一、学生可审阅的文件化项目状态；创建 `studio/outputs/working/` 保存派生产物，创建 `studio/outputs/final/` 保存已经过任务书、版本和文件 QA 的最终产物。

使用 bundled `scripts/init_project.py` 幂等初始化：已有项目状态时只返回续作状态，不覆盖。学生放入沙盒的原始任务书、图纸、模型、照片和数据一律保持只读；任何修改先复制到 working 目录并创建新版本。

只读环境或用户明确禁止写入时继续使用会话状态和续航快照，不创建替代状态文件。

任务书、rubric 和教师明确要求优先于通用设计课标准；通用标准只补足未说明的阶段门。安全、事实、学术诚信和作者性底线不可被课程要求覆盖。

外部 Adapter 只能写入分配的 working 子目录，必须返回 `RESULT.md`；文件存在不等于设计结论成立，项目状态只在复核和必要的学生确认后更新。

## 备选方案

### 继续只使用聊天状态

Interface 最小，但无法稳定支撑跨周、跨对话、跨文件和多 Adapter 作业，因此拒绝作为可写沙盒的默认方式。

### 建立数据库或跨项目学生档案

可以积累长期信息，但扩大同意、隐私、删除、错误归因和基础设施负担，不属于单作业沙盒目标，因此拒绝。

### 强制重排学生全部文件

目录看似整齐，但会破坏既有软件链接、版本习惯和学生原始材料，因此拒绝。Skill 只管理自己的 `studio/` 目录。

## 影响

- 学生可以跨对话恢复同一作业，并检查 AI 记录的决定和假设。
- 原始文件和派生产物有明确的写入 Seam，降低覆盖与版本漂移风险。
- 沙盒初始化脚本和模板进入 Skill 包，但测试、studio packet 和评测报告仍留在维护者仓库外部路径。
- 每次实质辅导需要读写或同步 `PROJECT.md`，维护者必须用多轮 Artifact journey 验证该行为。
