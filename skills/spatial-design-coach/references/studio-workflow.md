# Studio Workflow

Read this reference when entering from a project brief, choosing growth or rescue mode, locating the current stage, or coordinating architecture, urban planning, and landscape architecture.

## Build the project card

Use the card as a concise, student-visible shared snapshot and as temporary working memory. Show confirmed fields, important unknowns, and assumptions without dumping a long form. Do not create a persistent student profile or write a project file unless the user asks.

| Field | Extract | Why it changes the coaching |
| --- | --- | --- |
| Assignment | Discipline, course type, year if known | Sets expected depth without assuming lower standards |
| Site | Location, boundary, area, scale range | Defines which claims and representations are valid |
| People | Users, non-users, affected groups, client | Reveals benefit, exclusion, conflict, and daily life |
| Program | Required functions, quantities, performance | Separates obligations from negotiable choices |
| Constraints | Regulation, heritage, ecology, access, budget | Identifies hard limits and verification needs |
| Deliverables | Drawings, models, scales, formats, duration | Makes the route finishable as coursework |
| Time | Deadline, reviews, available work sessions | Selects growth or rescue mode |
| State | Current proposition, alternatives, drawings, model | Finds the real entry stage |
| Feedback | Tutor comments, rubric, unresolved objections | Distinguishes symptoms from the underlying conflict |
| Evidence status | Confirmed, inferred, assumed, unknown | Prevents invented certainty |

If the brief is long, return a compact reading under four labels: **must do**, **may decide**, **hidden tension**, and **must verify**. Do not paraphrase every paragraph.

## Low-information mode

When key material is missing:

1. State what is known from the student.
2. State no more than three consequential assumptions.
3. Ask one question whose answer could redirect the proposal.
4. Continue with reversible work: question map, alternative logic, diagram brief, or evidence checklist.
5. Mark any regulatory, environmental, social, dimensional, or site claim that cannot yet support a final decision.

Do not block useful progress merely because the brief is incomplete. Do not disguise a generic guess as a site-specific conclusion.

## Select the mode

### Growth mode

Use by default. Let the student attempt before showing a bounded example. Compare options, ask for a restatement in the student's own words, and finish with a small transfer test such as applying the same principle to another edge, section, or time period.

### Rescue mode

Use when the user explicitly requests emergency help or the deadline is within 72 hours.

1. List non-negotiable deliverables and remaining production time.
2. Freeze core decisions unless one makes submission impossible or contradicts the brief.
3. Identify the 1–3 problems with the greatest effect on legibility, completeness, or defense.
4. Define a minimum coherent submission before optional polish.
5. Work from high-leverage shared sources: one corrected plan can update diagrams, sections, captions, and speech.
6. Reserve time to audit consistency and rehearse questions.

Rescue mode is more direct, not less honest. It may specify a completion path, but pivotal design choices remain visible to the student.

## Seven-stage loop

Stages are a loop, not a waterfall. Enter at the current bottleneck; return upstream only when a decision cannot be defended or represented.

### 1. Decode the brief and real problem

- Separate the assigned object from the condition that makes it worth designing.
- Map actors, conflicts, scale, time, mandatory outcomes, and evaluation criteria.
- Reframe a topic such as “community center” or “resilience” into a situated problem.
- **Gate:** the student can explain who is affected, what is wrong now, and what the project can realistically change.

### 2. Form a design proposition

- Make a claim linking people, condition, spatial mechanism, intended consequence, and trade-off.
- Reject slogans that could describe any site or any form.
- Keep the proposition revisable rather than turning it into branding.
- **Gate:** a critic could disagree with it, and a drawing could test it.

### 3. Establish decision-changing evidence

- Seek site evidence, precedent mechanisms, relevant theory, and current requirements only for a live decision.
- Convert every finding into a design implication and a verification action.
- Record uncertainty and counterevidence.
- **Gate:** each retained input changes, supports, or rejects a design move.

### 4. Generate alternative families

- Produce 2–3 alternatives with different organizing mechanisms and value trade-offs.
- Hold brief compliance constant so the comparison is fair.
- Show each with the smallest comparable artifact: diagram, plan fragment, section, model, or scenario.
- **Gate:** the options would lead to observably different space, use, performance, and cost.

### 5. Translate into spatial systems

- Develop scale, geometry, access, publicness, program, structure, ground, water, ecology, climate, material, sequence, and time as relevant.
- Test the proposition in both plan and section and through at least one lived sequence.
- Trace key systems across the project boundary and across disciplines.
- **Gate:** the proposition is visible without relying on the title or narration.

### 6. Choose and iterate

- Name the dominant conflict, compare consequences, and select or hybridize deliberately.
- Protect the proposition while changing the mechanism when evidence fails it.
- Use a pass condition for each revision.
- **Gate:** major decisions, rejected alternatives, evidence, and accepted trade-offs can be explained.

### 7. Deliver and defend

- Build one narrative from problem and evidence through proposition, spatial response, performance, trade-off, and impact.
- Give every drawing a question to answer and a consistent project state.
- Rehearse claim, evidence, limitation, and response under challenge.
- **Gate:** required material is complete, mutually consistent, legible at delivery scale, and speakable within the allotted time.

## Integrate the three disciplines

Do not divide a joint project into “building,” “planning,” and “landscape” chapters that meet only on the final board. Trace shared spatial systems.

| Discipline focus | Questions it contributes |
| --- | --- |
| Architecture | How do program, body, room, structure, envelope, climate, material, and construction make the proposition inhabitable? |
| Urban planning | How do land, mobility, networks, governance, phasing, population, economics, and equity make it possible and consequential? |
| Landscape architecture | How do ground, water, habitat, vegetation, season, disturbance, maintenance, and succession make it perform over time? |

Run three integration checks:

- **Scale continuity:** territory or catchment → district → block or site → building or open space → room or detail.
- **Flow continuity:** people, water, habitat, energy, materials, services, access, and capital cross disciplinary boundaries.
- **Time continuity:** existing condition → intervention → construction or establishment → daily and seasonal use → adaptation.

At each boundary, ask who owns the decision, who benefits, what evidence supports it, and what downstream drawing must change.

## Close each review

End with one prioritized artifact the student can make before returning. Define its scale or viewpoint, the question it must answer, and the condition by which the next review will accept or reject the move.
